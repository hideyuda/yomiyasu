# 用途プロファイル: SNS投稿（sns）

X、Threads、LinkedInのように、タイムラインで流し読みされる短い投稿に使います。読むかどうかは1行目で決まります。リンターのオプションは`--profile sns`です。

---

## 1. 文体

- 書き手がふだん投稿している文体に合わせます。ボイスカードがあれば従います。分からないときは、Xは常体、LinkedInは「です・ます」にします。
- 1行目で言いたいことを言い切ります。「今日は〜について書きます」のような前置きから始めません。1行目に置くのは、元の文の主張か、目を引く具体的な事実（数字、やったこと、起きたこと）です。元の文にない教訓やまとめを作って1行目に置きません。
- 数量は算用数字で書きます（「十名」→「10名」）。
- 1文は10〜30字を目安にし、改行を多めに入れます。1段落は1〜3行にします。
- 口語は使ってかまいませんが、人間らしさスロップの上限を守ります。「〜なんですよね」「！」「実は」はそれぞれ1回までにします（`references/humanize/humanize-slop.md`）。

## 2. 長さ

- Xは全角140字（Xの数え方で280）以内にします。リンターはこの数え方で数えます。
- 140字に収まらないときは、まず元の文の主張を変えない範囲で削ります。削る順番は次のとおりです。SNSで読まれるのは具体的な話なので、数字や固有の出来事は最後まで残します。
  1. 経緯の前置き、言い換えの重複
  2. 一般化したまとめや教訓（元の文の主張そのものでなければ）
  3. 主張を支える事実のうち、2つ目以降のもの
  4. 数字、やったこと、結果（ここまで削らないと収まらないなら、投稿を分ける）
- 主張と、それを支える具体的な事実が1つも残らないときは、投稿を分けた案（「---」だけの行で区切る）にして、「変えたところ」に分けたことを書きます。
- 記事やページを紹介する投稿では、URLの分（Xの数え方で23、全角で約12字）を空けておきます。URLが分からないときは本文の最後に`[URL]`と書き、その分も数えます。
- LinkedInやFacebookでは300〜600字程度までかまいません。そのときはリンターのXの文字数の指摘を無視します。

## 3. 構造と記号

- 箇条書きは「・」で3項目までにします。
- Markdownの太字（**）、見出し（#）、表はSNSでは表示されないので使いません。
- 絵文字は1投稿に2個まで、ハッシュタグは2個までにします。項目ごとに絵文字を付けません。
- URLは最後に置きます。

## 4. 硬さと書き手の主観

- 硬さ辞書（`references/humanize/stiffness.md`）は強さ3で使います。
- 書き手の意見や感想は、元の文にあるものを前に出します。元の文にないときは作りません。書き分けるときに限り、`[ここに一言]`の空欄を入れてかまいません（必須ではありません）。空欄は2か所までで、字数に入れて数えます。

## 5. この用途に特有のAIっぽさ

- 「〜について解説します🧵」で始まるスレッド
- 【保存版】【必見】の見出し、「〜な件」「〜してみた」のタイトル
- 項目ごとの ✅ 📌 💡
- 最後の「参考になったらいいね・リポストお願いします」
- ハッシュタグを3つ以上並べる

## 6. 書き直しの例

元の文章（チーム運営を振り返るエッセイ、約500字）から、Xの1投稿に書き分けた例です。元の文章にある事実だけを使い、教訓のまとめより、やったことと数字を残しています。

```text
設計書を全員に書かせるルールは、3週間で誰も更新しなくなった。

テンプレートを「なぜ作ったか・やらなかったこと・壊れ方」の3項目に絞って、PRの説明欄に直接書く形にしたら、記載率は2割から9割近くまで上がった。
```

削った内容（レビューで「新人が読んで分かる？」と聞く習慣、半年後の結果）は、「変えたところ」に書きます。
